## 1. 核心布局原则：起始点重合

在**单继承**（Single Inheritance）中，派生类（Derived）和基类（Base）的内存起始地址是**完全一致**的。
- **逻辑原因**：C++ 认为“派生类对象就是一个基类对象”。
- **物理表现**：`Derived` 对象的开头部分就是 `Base` 的子对象。
- **例外**：只有在**多重继承**（如 `class C : public A, public B`）时，`C` 和 `B` 的地址才会产生偏移，因为 `B` 必须排在 `A` 后面。
---
## 2. 为什么地址会“+8”或“+16”？

即使 `Component` 是第一个成员，它的地址也往往不等于对象的起始地址。这主要受两个“幕后推手”影响：
### A. 虚函数表指针 (vptr)
- **触发条件**：只要类中定义了 `virtual` 函数（通常是虚析构函数）。
- **占用空间**：在 64 位系统下固定占用 **8 字节**。
- **位置**：为了多态效率，编译器强制将其放在对象的**绝对开头（Offset 0）**。
- **结果**：所有后续成员的地址至少从 **+8** 开始。
### B. 内存对齐 (Alignment)
- **规则**：为了 CPU 读取效率，成员的地址必须是其自身大小（或类中最大成员大小）的倍数。
- **现象**：如果一个 `int`（4 字节）后面跟着一个 `Component`（内部含 8 字节指针），编译器会在 `int` 后面插入 4 字节的 **Padding（填充）**。
- **结果**：这就是为什么 $8 (\text{vptr}) + 4 (\text{int})$ 往往变成了 **16** 而不是 **12**。
---
## 3. 时间（构造）vs 空间（布局）
这是最容易混淆的地方。记住一句话：**“图纸决定位置，顺序决定进场”。**

|**维度**|**决定因素**|**顺序规律**|
|---|---|---|
|**空间 (地址)**|**类声明的顺序**|1. 基类 $\rightarrow$ 2. 派生类成员 (按声明顺序)|
|**时间 (构造)**|**继承与包含关系**|1. 基类 $\rightarrow$ 2. 成员变量 $\rightarrow$ 3. 构造函数体|

- **即使 `Component` 属于 `Base` 且先构造**：它也必须待在 `Base` 预留的那个坑位里（通常在 `vptr` 之后）。
- **即使 `Derived` 最后构造**：它的起始地址依然从 `Base` 的头开始算起。
---
## 4. 总结对比表
假设在 64 位环境下，类定义了虚函数：

| **场景**                    | **Base 与 Derived 地址** | **Component 的偏移量** | **根本原因**                |
| ------------------------- | --------------------- | ------------------ | ----------------------- |
| **Component 在 Base 内**    | **相同**                | **+8**             | 被 `Base` 的 `vptr` 挤到了后面 |
| **Component 在 Derived 内** | **相同**                | **+8 或更多**         | 排在整个 `Base` 子对象后面       |
| **去掉 virtual 关键字**        | **相同**                | **+0**             | 没有 `vptr` 占位，成员即是开头     |
