## Unity

### 1. 怎么自己实现 Unity 中的 Animator，控制角色骨骼运动？
**核心思路：**
Unity 的动画本质是改变 Transform（Position, Rotation, Scale）随时间的变化。
1.  **数据结构设计**：需要一个数据结构来存储关键帧（Keyframes），每个关键帧包含时间戳和该时间点骨骼的 Transform 信息。
2.  **骨骼层级映射**：建立一个映射表（Map 或 List），将动画数据中的骨骼名称与实际场景中角色的 Transform 组件对应起来（通常通过 DFS 遍历骨骼层级）。
3.  **插值计算 (Interpolation)**：在 `Update` 循环中，根据当前播放的时间，找到前一个关键帧和后一个关键帧。
    * 位置和缩放使用线性插值 (`Vector3.Lerp`)。
    * 旋转必须使用球面插值 (`Quaternion.Slerp`) 以避免万向节锁并保证旋转平滑。
4.  **应用变换**：将计算出的局部变换矩阵赋值给对应的骨骼节点（`localRotation`, `localPosition`）。
5.  **混合 (Blending)**：如果需要从走过渡到跑，需要对两组计算出的 Transform 结果再进行一次加权插值。

## C++ (CPP)

### 1. 类的内存占用
1.  **空类的内存占用**：
    * **1 字节**。为了保证每个对象在内存中有唯一的地址，编译器会插入一个字节的占位符。
2.  **类中有 int、函数时**：
    * **Int**：占用 4 字节（32位/64位系统通常如此）。
    * **函数**：普通成员函数**不占用**对象实例的内存，它们存储在代码区。
    * **内存对齐**：需注意内存对齐（Padding）。如果类中只有 `int`，大小为 4；如果还有 `char`，可能因为对齐变成 8。
3.  **类中有虚函数时**：
    * 类内部会维护一个隐藏的指针：**虚函数表指针 (vptr)**。
    * 在 32 位系统下，指针占 4 字节；在 64 位系统下，指针占 8 字节。
    * 无论有多少个虚函数，只要有，就只增加这一个 vptr 的大小（针对单继承）。
<!--ID: 1773027655138-->


### 2. 虚函数
1.  **子类继承有虚函数的父类时，子类中有几个虚指针？**
    * **单继承**：子类中只有 **1 个** vptr。子类共享父类的虚表结构（但内容可能被覆盖）。
2.  **虚继承与菱形继承时，子类中有几个虚指针？**
    * 这取决于编译器实现（如 Itanium ABI 或 MSVC）。
    * 通常在**菱形继承**（非虚继承）中，底层的子类会继承两份基类，因此会有 **2 个** vptr。
    * 在**虚继承**中，为了保证基类只有一份副本，对象模型会变复杂。除了 vptr，通常还会增加一个 **vbptr (虚基类指针)** 指向虚基类表，或者通过偏移量实现。一般情况下是 vptr + vbptr 的开销。
3.  **构造函数和析构函数能否声明为虚函数？**
    * **构造函数**：**不能**。虚函数调用依赖 vptr，而 vptr 是在构造函数执行期间才初始化的。对象还没造出来，无法多态。
    * **析构函数**：**可以且强烈建议**（当类作为基类时）。如果析构函数不是虚函数，通过基类指针删除派生类对象时，只会调用基类的析构函数，导致派生类的资源未释放（内存泄漏）。

### 3. STL Map、Unordered Map 的底层实现
1.  **底层实现**：
    * **`std::map`**：**红黑树**（Red-Black Tree）。这是一种自平衡二叉查找树，保证 Key 有序，增删查复杂度均为 $O(\log N)$。
    * **`std::unordered_map`**：**哈希表**（Hash Table）。通过 Hash 函数映射到桶中，平均增删查复杂度为 $O(1)$。
2.  **Unordered Map 哈希冲突时是怎么处理的？**
    * 主流 STL 实现（如 libstdc++）通常使用**链地址法（Chaining）**。即每个桶（Bucket）维护一个链表，冲突的元素挂在链表上。
3.  **哈希冲突过于严重说明什么，此时怎么处理？**
    * **说明**：Hash 函数设计不好，或者负载因子（Load Factor）过高，导致大量元素堆积在同一个桶中，退化为链表查询，复杂度退化为 $O(N)$。
    * **处理**：
        1.  **扩容 (Rehash)**：STL 会自动增加桶的数量（通常翻倍），并重新计算所有元素的 Hash 位置。
        2.  **改进 Hash 函数**：自定义更均匀的 Hash 算法。
        3.  *(Java 8+ 的优化思路)*：当链表过长时转为红黑树，但 C++ 标准库目前主要还是纯链表。

## 操作系统
### 1. 内存布局，栈和堆的区别
- **布局**：代码段、数据段（全局/静态变量）、堆（向上增长）、栈（向下增长）。
- **栈 (Stack)**
    - 由编译器自动分配释放。
    - 存放局部变量、函数参数。
    - 分配速度快，空间较小（通常几 MB），内存连续。
- **堆 (Heap)**
    - 由程序员手动分配释放 (`new/malloc`)。
    - 空间大（受限于虚拟内存），分配速度较慢，容易产生内存碎片
<!--ID: 1773027655148-->

### 2. CPU 缓存为什么访问速度比内存快（局部性原理）
- **硬件层面**：Cache 使用 SRAM（静态随机存取存储器），比内存的 DRAM 速度更快但造价更高。
- **局部性原理**：
    1. **时间局部性**：如果一个数据被访问，不久后很可能再次被访问（如循环变量）。
    2. **空间局部性**：如果一个数据被访问，它临近的数据很可能马上被访问（如数组遍历）。Cache Line 一次读取一块连续内存，利用了这一点。
<!--ID: 1773027655151-->

### 3. 多线程与多进程的区别
- **进程**：操作系统资源分配的最小单位，拥有独立的地址空间。进程间通信（IPC）复杂。
- **线程**：CPU 调度的最小单位，是进程的执行流。线程间共享进程资源，通信简单但需同步。
1. **多线程会共用什么内存空间（栈还是堆）？**
    - **共用：堆 (Heap)**、全局数据区、代码区。
    - **独享：栈 (Stack)**（每个线程有独立的调用栈）、寄存器。
2. **操作系统处理多线程的模型（生产者-消费者模型）**
    - 这是一个经典的并发模型。
    - **生产者**：生成数据放入缓冲区。
    - **消费者**：从缓冲区取出数据处理。
    - **关键点**：需要使用**互斥锁 (Mutex)** 保护缓冲区不被同时修改，使用**条件变量 (Condition Variable)** 或信号量实现“空时等待”和“满时等待”的同步机制。

## 计算机网络

### 1. 协议选择
- **视频通话**：主要使用 **UDP**（如 RTP 协议）。因为视频对实时性要求高，允许少量丢包（画面卡顿一下），但不能忍受 TCP 重传带来的延迟。
- **HTTP**：主要使用 **TCP**。HTTP 需要可靠传输，保证网页数据不丢失、不乱序。_(注：HTTP/3 基于 QUIC，底层是 UDP，但面试一般答 TCP 即可)_
<!--ID: 1773027655156-->

### 2. HTTP 连接
1. **多次 HTTP 连接会创建几个 TCP 连接？**
    - **HTTP 1.0**：默认短连接，每请求一个资源（如图片、CSS）就建立一个 TCP，用完关闭。N 个资源 N 个 TCP。
    - **HTTP 1.1**：默认**长连接 (Keep-Alive)**。多个 HTTP 请求可以复用同一个 TCP 连接。
2. **哪个版本可以复用 TCP 连接？**
    - **HTTP 1.1** 及以上。
<!--ID: 1773027655159-->

### 3. TCP 的建立与断开
- **建立（三次握手）**：
    1. Client 发送 SYN（同步序列号）。
    2. Server 回复 SYN + ACK（确认收到，并发送自己的序列号）。
    3. Client 回复 ACK（建立连接）。
- **断开（四次挥手）**：
    1. Client 发送 FIN（结束）。
    2. Server 回复 ACK（收到结束请求，但我可能还有数据没发完，进入 Close-Wait）。
    3. Server 发送 FIN（数据发完了，请求结束）。
    4. Client 回复 ACK（确认，等待 2MSL 后彻底关闭）

## 第一部分：C++ 核心八股 (结合简历深度)

### 1. 智能指针 (Smart Pointers)
**核心点：** RAII (Resource Acquisition Is Initialization)，拒绝内存泄漏。
* **`std::shared_ptr`**:
    * **原理**：引用计数。每多一个指针指向对象，计数+1；析构时计数-1；归零时释放内存。
    * **线程安全**：引用计数的增减是**原子操作**（安全），但多线程读写同一个 `shared_ptr` 对象本身需要加锁。
* **`std::unique_ptr`**:
    * **原理**：独占所有权，不可拷贝（Copy Constructor 被 `delete`），只能移动（Move）。
    * **性能**：几乎零开销（和裸指针一样快）。
* **`std::weak_ptr`**:
    * **作用**：解决 `shared_ptr` 的**循环引用**（Circular Reference）导致内存无法释放的问题。
    * **特点**：不增加引用计数，必须提升为 `shared_ptr` (`lock()`) 才能访问对象。
<!--ID: 1773027655164-->


### 2. 结构体 (struct) vs 类 (class)
* **C++ 中的区别**：
    * 唯一本质区别是**默认访问权限**：`struct` 默认是 `public`，`class` 默认是 `private`。
    * `struct` 默认继承是 public 继承，`class` 默认是 private 继承。
* **C 语言中的 struct**：
    * C 的 struct 只是数据的聚合，不能有函数（虽然可以存函数指针），没有 `public/private` 概念。
<!--ID: 1773027655167-->


### 3. 虚函数 (Virtual Functions)
* **实现原理**：**虚表 (vtable)** 和 **虚表指针 (vptr)**。每个有虚函数的**类**有一张 vtable，每个**对象**头部有一个 vptr 指向该类的 vtable。
* **运行时多态**：通过基类指针调用虚函数时，编译器会生成代码去 vptr -> vtable 查表，找到实际的函数地址进行调用。
* **关键面试题**：**为什么析构函数必须是虚函数？**
    * 如果基类析构不是虚函数，当 `delete base_ptr`（指向派生类对象）时，只会调用基类的析构函数，派生类的成员（如申请的内存）不会被释放，导致**内存泄漏**。
<!--ID: 1773027655174-->


### 4. 左值 (L-value) vs 右值 (R-value)
[cite_start]**结合你简历中的“右值引用” **
* **定义**：
    * **左值**：有名字、有地址、持久的对象（如变量 `int a`）。
    * **右值**：无名字、临时的值（如字面量 `10`，函数返回的临时对象 `func()`）。
* **右值引用 (`T&&`)**：
    * 允许我们“窃取”临时对象的资源，避免深拷贝。
* **移动语义 (`std::move`)**：
    * 将左值强制转换为右值引用，告诉编译器“这个对象以后不用了，你可以把它的资源（堆内存指针）偷走”。
* **完美转发 (`std::forward`)**：
    * 在模板编程中，保持参数原本的左/右值属性传递给下一个函数。

### 5. 引用 vs 指针
| 特性 | 指针 (Pointer) | 引用 (Reference) |
| :--- | :--- | :--- |
| **本质** | 一个变量，存的是地址 | 一个已存在变量的别名 |
| **空值** | 可以为 `nullptr` | **必须初始化**，不能为空 |
| **重指向** | 可以改变指向 | 初始化后**不可改变** |
| **内存** | 占用指针大小内存 (4/8字节) | 汇编底层通常也是指针实现，但不占额外语义空间 |
| **多级** | 有二级指针 (`int**`) | 没有引用引用 (`int&&` 是右值引用) |

### 题目 1：二叉树路径和 (Path Sum)
**场景**：LeetCode 113. Path Sum II (找出所有路径)
**思路**：DFS (回溯法)。
<!--ID: 1773027655183-->


```cpp
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode(int x) : val(x), left(NULL), right(NULL) {}
};

class Solution {
public:
    vector<vector<int>> result;
    vector<int> path;

    void dfs(TreeNode* node, int targetSum) {
        if (!node) return;

        path.push_back(node->val);
        targetSum -= node->val;

        // Leaf node check AND sum match
        if (!node->left && !node->right && targetSum == 0) {
            result.push_back(path);
        }

        dfs(node->left, targetSum);
        dfs(node->right, targetSum);

        // Backtrack: pop the current node before returning to parent
        path.pop_back();
    }

    vector<vector<int>> pathSum(TreeNode* root, int targetSum) {
        dfs(root, targetSum);
        return result;
    }
};

class Solution {
public:
    int uniquePaths(int m, int n) {
        // 优化：只需要一维数组即可，因为当前行只依赖上一行
        // dp[j] 表示到达当前行第 j 列的路径数
        vector<int> dp(n, 1);

        for (int i = 1; i < m; ++i) {
            for (int j = 1; j < n; ++j) {
                // dp[j] (新) = dp[j] (旧，相当于上一行的值) + dp[j-1] (当前行左边的值)
                dp[j] = dp[j] + dp[j - 1];
            }
        }
        return dp[n - 1];
    }
};


// 片段着色器中
vec3 BlinnPhong(vec3 normal, vec3 fragPos, vec3 lightPos, vec3 viewPos) {
    // 基础向量
    vec3 N = normalize(normal);
    vec3 L = normalize(lightPos - fragPos);
    vec3 V = normalize(viewPos - fragPos);
    
    // Ambient
    vec3 ambient = vec3(0.1);

    // Diffuse
    float diff = max(dot(N, L), 0.0);
    vec3 diffuse = diff * vec3(1.0); // 假设白光

    // Specular (Blinn-Phong)
    vec3 H = normalize(L + V); // 记住这一行！
    float spec = pow(max(dot(N, H), 0.0), 32.0);
    vec3 specular = spec * vec3(1.0);

    return ambient + diffuse + specular;
}
