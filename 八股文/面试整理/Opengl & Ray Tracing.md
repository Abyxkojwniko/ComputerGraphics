# 第一部分：OpenGL (实时光栅化管线)

> **一句话理解**：OpenGL 是一个**状态机**。你设置各种开关（深度测试、混合模式），绑定各种数据（VBO、纹理），然后喊一声“Draw！”，GPU 就会按照你设定的状态把三角形画出来。
<!--ID: 1773027655207-->


## 1. 核心对象与缓冲 (Buffers & Objects) [🔥 必考]

### 1.1 VBO, VAO, EBO (数据怎么给 GPU？)
* **VBO (Vertex Buffer Object)**: **存数据的地方**。显存里的一块地，存顶点坐标、颜色、法线、UV。
    * *TinyRenderer 类比*：你的 `model->verts()` 数组。
* **VAO (Vertex Array Object)**: **数据的说明书**。告诉 GPU：“VBO 里前 3 个数是坐标，后 2 个是 UV，中间空 3 个字节”。
    * *面试考点*：**为什么要 VAO？** 它是为了快速切换状态。切换一个 VAO，就自动绑定了所有关联的 VBO 和属性格式，不用每次 Draw 都重新解释一遍数据。
* **EBO (Element Buffer Object)**: **顶点的索引**。告诉 GPU：“画第 0、1、2 个点组成三角形”。
    * *优点*：复用顶点，节省显存（比如立方体 8 个顶点能组成 12 个面，不用存 36 个顶点）。
<!--ID: 1773027655210-->


### 1.2 FBO (Frame Buffer Object) (高级考点)
* **定义**：**画布**。默认画在屏幕上（Default Framebuffer），但你可以创建 FBO 画到一张纹理上（Render to Texture）。
* **用途**：
    1.  **后处理 (Post-processing)**：先画到纹理，再对纹理做模糊/调色。
    2.  **阴影贴图 (Shadow Map)**：从光源视角画一遍，只存深度到 FBO。
* **🔥 易考点**: **FBO 包含什么？** 包含 Color Attachment（颜色图）、Depth/Stencil Attachment（深度/模板图）。

## 2. 渲染管线 (The Pipeline) [⚡️ 重难点]

面试官会问：“从 `glDrawArrays` 到屏幕出现像素，经历了什么？”
<!--ID: 1773027655216-->


1.  **Vertex Shader (顶点着色)**:
    * **输入**: 一个顶点。
    * **任务**: MVP 变换 (`Local -> Clip`)。
    * **输出**: 裁剪空间坐标 `gl_Position`。
2.  **Primitive Assembly & Clipping (图元组装与裁剪)**:
    * 把点连成三角形，切掉视锥体外面的部分。
3.  **Rasterization (光栅化)**:
    * **输入**: 屏幕上的三角形。
    * **任务**: 找出三角形覆盖了哪些像素，生成 **Fragment (片元)**。
    * *TinyRenderer 类比*：你的 `triangle()` 函数。
4.  **Fragment Shader (片元着色)**:
    * **输入**: 一个片元（带插值后的 UV、法线）。
    * **任务**: 算颜色（纹理采样 + 光照）。
    * *TinyRenderer 类比*：你的 `shader.fragment()`。
5.  **Per-Sample Operations (测试与混合)** [☠️ 死亡细节]:
    * **Scissor Test** (裁剪测试) -> **Stencil Test** (模板测试) -> **Depth Test** (深度测试)。
    * **Blending** (颜色混合)：如果半透明，和 framebuffer 里已有的颜色混合。

---

## 3. 坐标系变换 (Coordinate Systems)

* **Local** (模型) -> **World** (世界) -> **View** (相机) -> **Clip** (裁剪) -> **NDC** (归一化) -> **Screen** (屏幕)。
* **🔥 易考点**:
    * **Q: 顶点着色器最后输出的是什么坐标？**
    * **A**: **Clip Coordinates** (裁剪空间，即 $w$ 还没除之前的坐标)。透视除法是硬件在光栅化前自动做的。

# 第二部分：光线追踪 (Ray Tracing)

> **一句话理解**：光栅化是“把几何体投影到屏幕上”，光线追踪是“从眼睛发射光线去逆向寻找几何体”。后者符合物理规律，但极其慢。
<!--ID: 1773027655221-->


## 1. 核心原理：渲染方程 (The Rendering Equation) [👑 王冠上的宝石]

$$L_o(p, \omega_o) = L_e(p, \omega_o) + \int_{\Omega^+} L_i(p, \omega_i) f_r(p, \omega_i, \omega_o) (n \cdot \omega_i) d\omega_i$$
<!--ID: 1773027655224-->


别怕公式！面试只需要懂这四项是什么：
1.  **$L_o$ (出射光)**: 眼睛看到的颜色。
2.  **$L_e$ (自发光)**: 物体自己发的光（灯泡）。
3.  **$\int$ (积分)**: 把四面八方飞进来的光加起来。
4.  **$L_i$ (入射光)**: 别的物体反射过来的光。
5.  **$f_r$ (BRDF)**: **核心！** 材质属性。决定了光打上来是发生镜面反射（金属）还是漫反射（木头）。
    * *你的 GeoPBR 项目就是生成这个 $f_r$ 的参数 (Albedo, Roughness, Metallic)*。
6.  **$n \cdot \omega_i$ (余弦项)**: 光线越倾斜，能量越弱（Lambert 定律）。

---

## 2. 加速结构 (Acceleration Structures) [⚡️ 必考]

光线追踪最慢的地方是“求交”（Intersection）。场景有一万个三角形，不能每一条光线都遍历一万次。
<!--ID: 1773027655226-->


* **BVH (Bounding Volume Hierarchy)**:
    * **原理**: 把场景里的物体用盒子（AABB）包起来。
    * **逻辑**: 光线撞到了大盒子吗？没撞到 -> 里面的东西都不用看了。撞到了 -> 打开盒子看里面的小盒子。
    * **优点**: 也是目前 GPU 光追（RTX）硬件加速的核心。
* **KD-Tree**: 以前常用，现在 BVH 更流行（因为 BVH 更新动态物体更方便）。

---

## 3. 蒙特卡洛积分 (Monte Carlo Integration)

* **问题**: 渲染方程里的积分 $\int$ 算不出来（光线太多了）。
* **解法**: **摇骰子 (随机采样)**。
* **逻辑**: 我不知道精确值，但我随机射 $N$ 条光线，算出平均值。$N$ 越大，结果越准，噪点越少。
* **Path Tracing (路径追踪)**:
    * 从相机射出光线 -> 撞到点 A -> 随机弹射到点 B -> 随机弹射到光源。
    * 把这条路径上的能量加起来。
<!--ID: 1773027655229-->


---

## 4. 重要性采样 (Importance Sampling) [💎 进阶加分项]

* **问题**: 如果物体很光滑（镜子），光线明明只会往反射方向走，你还往四面八方瞎射，99% 的光线都是黑的（浪费）。
* **解法**: **根据材质 (BRDF) 的形状来射**。
    * **粗糙度低 (Roughness $\downarrow$)**: 往反射方向密集发射光线。
    * **粗糙度高 (Roughness $\uparrow$)**: 往半球均匀发射。
* **你的 GeoPBR 关联**: 你的 **Roughness Map** 就是用来指导光追渲染器做重要性采样的 PDF (概率密度函数)。

# 第三部分：OpenGL vs 光线追踪 (对比考点)

| 维度 | OpenGL (光栅化) | Ray Tracing (光线追踪) |
| :--- | :--- | :--- |
| **核心逻辑** | 物体找像素 (Object-Order) | 像素找物体 (Image-Order) |
| **全局光照 (GI)** | 很难做 (要靠 Shadow Map, Lightmap 烘焙等 Hack 手段) | 天然支持 (光线弹射自然产生 GI) |
| **反射/折射** | 很难 (Screen Space Reflection 只能反射屏幕内的) | 天然支持 (光线直接追踪下去) |
| **性能** | 极快 (O(N) 复杂度) | 慢 (依赖 BVH 降到 O(logN)，但常数大) |
| **应用场景** | 传统游戏 (CS:GO, LOL) | 电影渲染, 3A 大作开启 RTX 模式 |

# 第四部分：面试常问 Q&A (背诵版)

### Q1: 深度测试 (Depth Test) 是在 Fragment Shader 之前还是之后？
* **A**: 标准管线是在**之后**。但现代 GPU 有 **Early-Z** 技术，可以在 Shader **之前**就判断深度，如果被遮挡了就直接不跑 Shader 了（省钱）。
<!--ID: 1773027655237-->


### Q2: 什么是 Draw Call？为什么它多了会卡？
* **A**: Draw Call 是 CPU 命令 GPU 画画的指令。
* 每一次 Draw Call，CPU 都要准备数据、设置状态、检查错误，这有很大的 **CPU Overhead (开销)**。
* **优化**: Batching (合批)，把一堆小东西合在一起，一次 Draw Call 画完。
<!--ID: 1773027655240-->


### Q3: 光线追踪里的“俄罗斯轮盘赌 (Russian Roulette)”是什么？
* **A**: 决定光线**什么时候停止弹射**的策略。
* 光线不能无限弹射下去（死循环）。如果你设死“弹 5 次”，能量会损失。
* **策略**: 每次弹射有一个概率 $P$ 继续，$(1-P)$ 停止。如果继续，能量除以 $P$（能量守恒）。这保证了结果是**无偏 (Unbiased)** 的。
