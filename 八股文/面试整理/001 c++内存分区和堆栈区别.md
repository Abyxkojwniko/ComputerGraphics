## 请简要介绍一下 C++ 程序的内存分区有哪些？ 重点谈谈 **栈（Stack）** 和 **堆（Heap）** 的区别。 **追问：从底层原理（汇编或操作系统角度）解释，为什么栈上的内存分配要比堆快得多？**

### 1.C++程序的内存布局通常分为以下5个部分（从高地址到低地址）
1.栈区：根据编译器自主分配，存放函数的参数值，局部变量，返回地址等
2.堆区：由程序员分配和释放，如果不释放，程序结束时可能由os回收
3.全局/静态存储区：全局变量和静态变量（static）存放在这里，包括.data(已经初始化)和.bss(未初始化)
4.常量存储区：存放常量字符串等，不允许修改
5.代码区：存放函数体的二进制代码

### 2.栈和堆的区别
|**特性**|**栈 (Stack)**|**堆 (Heap)**|
|---|---|---|
|**管理方式**|编译器自动管理|程序员手动控制 (`new`/`delete`)|
|**空间大小**|小（通常 1MB - 8MB）|大（受限于虚拟内存，32位可达 G 级）|
|**碎片问题**|无（先进后出，连续）|有（频繁分配释放导致碎片）|
|**生长方向**|向下（高地址 -> 低地址）|向上（低地址 -> 高地址）|
|**分配效率**|**极高**|**较低**|3

### 3.为什么栈比堆快
栈比堆快主要体现在**指令级操作**和**缓存命中**两个维度：
1. **指令级效率 (Instruction Level)：**
    - **栈：** 分配内存仅仅是 CPU **移动栈指针**（Register `ESP`/`RSP`）。通常只需要一条汇编指令（如 `sub rsp, size`），不仅仅是 O(1)，更是纳秒级的。
    - **堆：** `malloc`/`new` 是库函数。它需要运行复杂的分配算法（如查找空闲链表、Best-fit 搜索、分割内存块）。如果堆内存耗尽，还涉及**系统调用**（如 `brk`/`mmap`），产生用户态到内核态的上下文切换，开销巨大。
2. **缓存局部性 (Data Locality)：**
    - **栈：** 内存是连续分配的，且经常被反复访问（栈顶附近）。这极大地利用了 **CPU L1/L2 Cache**，命中率极高。
    - **堆：** 分配的内存块散落在虚拟地址空间的各个位置（链表连接），频繁跳转访问会导致严重的 **Cache Miss**（游戏引擎性能杀手）。
