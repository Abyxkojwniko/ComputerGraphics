## 1. 基础算法：光栅化 (Rasterization)

### 1.1 Bresenham 画线算法
* **核心逻辑**：仅使用**整数加法**和**位运算**绘制直线，避免浮点数计算和乘除法。
* **🔥 易考点**：
    * **Q: 为什么要用 Bresenham 而不是 `y = kx + b`？**
    * **A**: 浮点数计算慢且有精度误差。Bresenham 通过累加误差项 `error`，当 `error > 0.5` 时进位，全程纯整数运算，效率极高。
<!--ID: 1773027654890-->


### 1.2 三角形光栅化 (Triangle Rasterization)
* **核心逻辑**：现代光栅化器通常使用 **包围盒 + 重心坐标 (Bounding Box + Barycentric)** 方法，而不是扫描线法（Scanline）。
* **🔥 易考点**：
    * **Q: 为什么不用扫描线算法？**
    * **A**: 扫描线算法逻辑复杂（需要处理平底/平顶三角形分叉），且难以并行。重心坐标法像素之间相互独立，极易在 GPU 上大规模并行化。
    * **Q: 如何判断点在三角形内？**
    * **A**: 计算重心坐标 $(u, v, w)$。如果 $u \ge 0, v \ge 0, w \ge 0$ (且 $u+v+w=1$)，则点在三角形内。也可以用叉乘判断点是否在三条边的同一侧。

## 2. 空间变换 (Coordinate Spaces & Matrices) [⚡️重难点]

### 2.1 齐次坐标 (Homogeneous Coordinates)
* **💡 核心概念**：引入 $w$ 分量，$(x, y, z, 1)$ 表示点，$(x, y, z, 0)$ 表示向量。
* **🔥 易考点**：
    * **Q: 为什么需要齐次坐标？**
    * **A**: 1. 统一处理**平移**（线性变换无法表示平移，必须升维）。2. 处理**透视投影**（通过 $w$ 分量存储深度信息，以便进行透视除法）。
<!--ID: 1773027654896-->


### 2.2 视图变换 (View Matrix / LookAt)
* **推导逻辑**：相机不动，世界反向运动。
* **步骤**：
    1.  **平移**：将相机移回原点 $T(-Eye)$。
    2.  **旋转**：计算相机的基向量 $Right(\vec{r}), Up(\vec{u}), Forward(\vec{f})$。
        * 正向旋转矩阵（相机转世界）是 $[\vec{r}, \vec{u}, \vec{f}]$ (列向量)。
        * **逆变换**（世界转相机）是其逆矩阵。因旋转矩阵是**正交矩阵**，逆等于转置。
        * 所以 View 旋转矩阵是 $[\vec{r}, \vec{u}, \vec{f}]^T$ (行向量)。
* **🔥 易考点**：
    * **Q: 为什么 View Matrix 的旋转部分是基向量横着放？**
    * **A**: 因为它是“相机坐标系转世界坐标系”的逆变换，利用了正交矩阵 $R^{-1} = R^T$ 的性质。
<!--ID: 1773027654899-->


### 2.3 投影变换 (Projection Matrix) [⚡️最难推导]
* **透视投影 (Perspective Projection)**：
    * **目的**：将视锥体 (Frustum) 挤压成标准立方体 (CVV, $[-1, 1]^3$)。
    * **关键操作**：矩阵最后一行通常是 $[0, 0, -1, 0]$。这使得变换后的结果 $P_{clip} = (x', y', z', -z_{view})$。即 $w_{clip}$ 存储了原始深度的负值。
* **透视除法 (Perspective Division)**：
    * 硬件自动执行 $(x/w, y/w, z/w)$。
    * **近大远小**就在这一步发生（$x, y$ 被深度 $z$ 除小了）。
* **🔥 易考点**：
    * **Q: NDC 空间下的 Z 是线性的吗？**
    * **A**: **不是**。$Z_{ndc} = A + \frac{B}{Z_{view}}$。这是双曲线关系。导致 Z-Buffer **近处精度高，远处精度低**（容易发生 Z-Fighting）。
<!--ID: 1773027654902-->

## 3. 深度测试与 Z-Buffer

* **核心逻辑**：每个像素存储一个最近的深度值。光栅化新像素时，比较 `current_z` 和 `zbuffer[x][y]`。
* **🔥 易考点**：
    * **Q: Z-Buffer 存的是什么值？**
    * **A**: 存的是经过透视除法后的 $Z_{ndc}$（通常映射到 $[0, 1]$），而不是相机空间的线性 $Z$。这也是为什么需要透视校正插值的原因。

## 4. 透视校正插值 (Perspective Correct Interpolation) [☠️ 死亡考点]

这是软光栅面试中**含金量最高**的问题。
<!--ID: 1773027654908-->


### 4.1 问题描述
在屏幕空间（Screen Space）利用重心坐标直接插值属性（如纹理坐标 $UV$、颜色、法线）是**错误**的。
* **原因**：透视投影是非线性变换。3D 空间中线段的中点，投影到 2D 屏幕后，**并不是** 2D 线段的中点（通常会偏向相机一侧）。因此 2D 屏幕空间的重心坐标 $u, v, w$ 不能直接用于 3D 属性插值。
<!--ID: 1773027654911-->


### 4.2 解决方案
必须在**倒数空间**进行插值。数学推导证明：虽然属性 $I$ 关于屏幕坐标不线性，但 **$I/Z$** 关于屏幕坐标是线性的。
<!--ID: 1773027654913-->


### 4.3 正确流程
1.  **顶点着色器**：算出顶点的 $\frac{1}{Z}$ 和 $\frac{UV}{Z}$。
2.  **光栅化阶段**：利用屏幕重心坐标插值，得到当前像素的 $(\frac{1}{Z})_{interp}$ 和 $(\frac{UV}{Z})_{interp}$。
3.  **片段着色器前**：恢复真实的 $UV$。
    $$UV_{correct} = \frac{(\frac{UV}{Z})_{interp}}{(\frac{1}{Z})_{interp}}$$
<!--ID: 1773027654916-->


* **🔥 易考点**：
    * **Q: 为什么我的地板纹理看起来歪了/扭曲了？**
    * **A**: 因为没有做透视校正插值，直接在屏幕空间线性插值 $UV$ 导致的仿射纹理映射（Affine Texture Mapping）错误。

## 5. 着色与材质 (Shading & Material)

### 5.1 Phong vs Gouraud
* **Gouraud**: 顶点算光照，中间插值颜色。**缺点**：高光会变丑或消失（如果高光在三角形中间）。
* **Phong**: 插值法线，像素算光照。**优点**：高光细腻。**缺点**：计算量大。
<!--ID: 1773027654919-->


### 5.2 法线贴图 (Normal Mapping) [⚡️重难点]
* **TBN 矩阵**：用于将 **切线空间 (Tangent Space)** 的法线转换到 **世界空间**。
    * Tangent ($T$), Bitangent ($B$), Normal ($N$)。
    * $N_{world} = TBN \cdot N_{texture}$。
* **🔥 易考点**：
    * **Q: 为什么法线贴图是蓝紫色的？**
    * **A**: 因为在切线空间中，“垂直于表面”的方向是 Z 轴 $(0, 0, 1)$。映射到 RGB 空间 $(x+1)/2$ 后，就是 $(0.5, 0.5, 1.0)$，即淡蓝色。
<!--ID: 1773027654922-->


### 5.3 阴影映射 (Shadow Mapping)
* **两趟 Pass**：
    1.  **Light Pass**: 从光源视角渲染场景深度 -> 生成 Shadow Map。
    2.  **Camera Pass**: 正常渲染，将像素变换到光源空间，对比深度。
* **🔥 易考点**：
    * **Q: 什么是 Shadow Acne（自遮挡）？怎么解？**
    * **A**: 精度误差导致物体表面自己遮挡自己（出现黑色条纹）。解法是加一个 **Bias (偏移量)**。
    * **Q: 什么是 Peter Panning（悬浮）？**
    * **A**: Bias 加太大了，阴影和物体分离了。
